## 추천: MLX-LM 중심 + Ollama 병행

M4 48GB면 상당히 여유로운 사양이라 **MLX-LM을 메인**으로 쓰고, 빠른 테스트나 앱 연동용으로 **Ollama를 보조**로 두는 조합을 추천합니다.

## 이유

**MLX-LM이 메인인 이유**
- Apple Silicon 전용으로 만들어져서 같은 모델이라도 llama.cpp나 transformers(MPS)보다 대체로 빠르고 메모리 효율이 좋습니다.
- 파이썬 코드로 모델 로드, 생성, 채팅 템플릿을 직접 제어할 수 있습니다.
- 앞에서 만든 `messages` 형식 데이터로 `mlx_lm.lora` LoRA 파인튜닝까지 같은 도구에서 할 수 있습니다. 48GB면 7~8B급은 여유 있게, 14B급도 4bit 양자화(QLoRA 방식)로 가능한 범위입니다.

**Ollama를 병행하는 이유**
- `ollama run`으로 모델을 빠르게 받아서 성능을 비교해 볼 수 있습니다.
- OpenAI 호환 API(`localhost:11434`)를 제공해서 다른 앱, 에디터 플러그인, 프레임워크와 붙이기 쉽습니다.

## 48GB에서 쓸 수 있는 모델 크기

통합 메모리 48GB 중 macOS와 다른 앱 몫을 빼면 모델에 안정적으로 쓸 수 있는 양은 대략 30~36GB입니다.

| 크기 (4bit 기준) | 메모리 사용 | 비고 |
|---|---|---|
| 7~8B | 약 5~6GB | 매우 쾌적, 파인튜닝도 여유 |
| 14B | 약 9~10GB | 쾌적, 품질과 속도의 균형이 좋음 |
| 27~32B | 약 17~20GB | 실사용 가능, 이 사양의 최적 구간 |
| 70B | 약 40GB | 메모리가 빠듯해서 비추천 |

가장 만족도가 높은 구간은 **14B~32B 4bit 모델**입니다. 여기에 KV 캐시(컨텍스트가 길수록 증가)까지 고려해야 하니 70B급은 피하는 게 좋습니다.

## 시작 순서

```bash
# 1. MLX-LM 설치
uv add mlx-lm

# 2. 중간 크기 모델로 먼저 테스트
uv run mlx_lm.chat --model mlx-community/Qwen2.5-14B-Instruct-4bit
```

```python
from mlx_lm import load, generate

model, tokenizer = load("mlx-community/Qwen2.5-14B-Instruct-4bit")

messages = [{"role": "user", "content": "파이썬에서 리스트를 뒤집는 방법을 알려주세요."}]
prompt = tokenizer.apply_chat_template(messages, add_generation_prompt=True)

print(generate(model, tokenizer, prompt=prompt, max_tokens=300))
```

한국어 성능이 중요하면 같은 크기대에서 Qwen, Gemma 계열 등 몇 가지를 돌려보고 비교하세요. 모델 이름은 새 버전이 계속 나오니 허깅페이스 `mlx-community`에서 최신 목록을 확인하는 것이 좋습니다.

## 다른 방법을 추천하지 않는 경우

- **llama-cpp-python**: 이미 GGUF 파일이 있거나 GGUF 전용 모델을 써야 할 때만 필요합니다. 빌드 옵션(`CMAKE_ARGS`)도 번거롭습니다.
- **transformers + MPS**: 원본 가중치를 그대로 쓰거나 최신 연구용 모델을 실험할 때 외에는 MLX보다 느리고 메모리도 더 씁니다. fp16 기준 14B가 약 28GB라 48GB에서는 빠듯합니다.

## 팁

- 긴 컨텍스트나 여러 모델을 동시에 돌릴 계획이라면 활동 상태 보기(Activity Monitor)의 메모리 압력 그래프가 노란색, 빨간색으로 올라가는지 확인하세요. 올라가면 모델 크기나 `max_tokens`, 컨텍스트 길이를 줄여야 합니다.
- 발열이 신경 쓰이는 장시간 작업은 전원을 연결하고 진행하세요. 배터리 모드에서는 성능이 제한될 수 있습니다.
