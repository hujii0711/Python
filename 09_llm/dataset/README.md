# RAG 데이터셋 다루기

RAG 시스템을 만들 때 실제로 시간을 가장 많이 쓰는 곳은 모델이 아니라 데이터다.
문서를 모으고, 정제하고, 중복을 걷어내고, 자르고, 평가셋을 만들고, 점수를 재는 과정을
10단계로 나눠 실행해 본다.

각 단계는 `build/` 에 JSONL 산출물을 남기고 다음 단계가 그것을 읽는다.
중간부터 다시 돌리거나 산출물만 따로 열어 보기 쉽다.

## 예제 10개

| 파일                       | 주제            | 배우는 것                                                   |
| -------------------------- | --------------- | ----------------------------------------------------------- |
| `01_build_corpus.py`       | 코퍼스 구축     | 형식이 다른 파일을 하나의 스키마로 통일, 고정 `doc_id`      |
| `02_clean_text.py`         | 정제            | HTML·보일러플레이트·전각/제어문자 제거, 규칙별 영향 측정    |
| `03_dedup.py`              | 중복 제거       | 정확 중복(sha256) + 근사 중복(자카드 / 임베딩) 비교         |
| `04_chunk_and_stats.py`    | 청킹 + 분석     | 청크 크기 후보 비교, 글자 수와 토큰 수 분포, 이상 청크 탐지 |
| `05_enrich_metadata.py`    | 메타데이터 보강 | 절 제목 경로, 언어 판별, 코드 포함 여부, 문서 내 위치       |
| `06_make_eval_set.py`      | 평가셋 생성     | FAQ / 제목 / 사람 작성 세 방식과 각각의 난이도              |
| `07_evaluate_retrieval.py` | 검색 평가       | Recall@k, Hit@k, MRR, nDCG@k 를 직접 계산                   |
| `08_hard_negatives.py`     | 하드 네거티브   | 파인튜닝용 (질문, 정답, 오답) 트리플렛 만들기               |
| `09_split_dataset.py`      | 데이터 분할     | 문서 단위 그룹 분할로 누수 방지, 층화, 재현 가능한 배정     |
| `10_dataset_report.py`     | 데이터셋 카드   | 단계별 건수·분포·지표·체크섬을 마크다운으로 기록            |

| 그 외                     | 설명                                                                |
| ------------------------- | ------------------------------------------------------------------- |
| `_common.py`              | 경로, JSONL 입출력, 해시, 임베딩 로더, OS 분기                      |
| `raw/`                    | 코퍼스 원본. 중복·HTML·머리말/꼬리말 같은 잡음을 일부러 넣어 두었다 |
| `eval/eval_questions.csv` | 사람이 직접 쓴 평가 질문. 코퍼스에 섞이지 않게 `raw/` 바깥에 둔다   |
| `build/`                  | 단계별 산출물. git 에는 올리지 않는다                               |

## 실행

```powershell
cd C:\Python\09_llm
uv sync

uv run dataset\01_build_corpus.py
uv run dataset\02_clean_text.py
uv run dataset\03_dedup.py
uv run dataset\04_chunk_and_stats.py
uv run dataset\05_enrich_metadata.py
uv run dataset\06_make_eval_set.py
uv run dataset\07_evaluate_retrieval.py
uv run dataset\08_hard_negatives.py
uv run dataset\09_split_dataset.py
uv run dataset\10_dataset_report.py
```

macOS 는 경로 구분자만 바뀐다.

```bash
cd ~/Python/09_llm
uv run dataset/01_build_corpus.py
```

순서대로 실행해야 한다. 앞 단계 산출물이 없으면 어느 스크립트를 먼저 돌려야 하는지
안내하고 멈춘다. 03, 07, 08 은 임베딩 모델(bge-m3, 약 2.3GB)을 쓴다.

## 데이터 흐름

```
raw/ 12개 파일
  |  01  형식별 로드 + 스키마 통일          -> 17건
  |  02  정제 (짧은 문서 1건 제거)          -> 16건
  |  03  중복 제거 (정확 1건 + 근사 1건)    -> 14건
  |  04  청킹 (chunk_size=500, overlap=80)  -> 21개 청크
  |  05  메타데이터 보강 (section, lang, has_code, position)
  |
  +--> 06 평가셋 31건 --> 07 검색 지표 --> 10 데이터셋 카드
  +--> 08 하드 네거티브 트리플렛 31건
  +--> 09 train 15 / valid 3 / test 3 청크
```

07 의 실제 결과 (bge-m3, top-k 검색)

| 질문 출처 | 건수 | Recall@3 | MRR   |
| --------- | ---- | -------- | ----- |
| 제목 기반 | 13   | 1.000    | 1.000 |
| FAQ 기반  | 6    | 1.000    | 1.000 |
| 사람 작성 | 12   | 0.833    | 0.819 |

## 알아두면 좋은 점

**식별자를 고정한다** — `doc_id` 는 파일 이름, `chunk_id` 는 `doc_id::번호` 로 고정했다.
다시 만들어도 같은 id 가 나오기 때문에 평가셋의 정답이 계속 유효하고, 벡터DB 에
다시 색인해도 중복이 쌓이지 않는다. (`rag/04_index.py` 가 같은 규칙을 쓴다.)

**평가 자료는 코퍼스에 넣지 않는다** — `eval/eval_questions.csv` 를 `raw/` 에 두면
01 단계가 그것까지 문서로 읽어 색인한다. 그러면 질문이 자기 자신을 검색해 맞히는 꼴이
되어 점수가 의미를 잃는다. 디렉터리를 나눠 두면 실수로 섞일 일이 없다.

**정제 규칙은 영향을 측정한다** — 글자 수 변화만 보면 NFKC 정규화처럼 길이가 그대로인
규칙이 아무 일도 안 한 것처럼 보인다. 02 는 "줄어든 글자 수"와 "바뀐 문서 수"를 함께 센다.

**HTML 제목은 지우지 않고 마크다운으로 옮긴다** — `<h2>` 를 그냥 태그로 취급해 날리면
05 단계에서 "이 문단이 어느 절에 속하는지"를 복원할 수 없다.

**평가셋은 출처별로 난이도가 다르다** — 제목에서 만든 질문은 문서 표현을 그대로 쓰기
때문에 거의 다 맞는다(MRR 1.000). 사람이 쓴 질문은 문서에 없는 단어를 쓰므로 점수가
낮다(MRR 0.819). 위 표가 그 차이다. 제목 기반 점수만 보고 검색이 잘 된다고 판단하면 안 된다.

**분할은 문서 단위로 한다** — 같은 문서의 청크가 train 과 test 로 갈리면 내용이 거의
같아서 test 점수가 실제보다 높게 나온다. 09 는 문서를 통째로 한쪽에 보내고 누수를 검사한다.

**카테고리별로 비율을 적용하면 안 된다** — 문서가 2~3개뿐인 카테고리에 15%를 적용하면
반올림되어 0이 된다(실제로 처음엔 valid 가 통째로 비었다). 09 는 카테고리를 라운드로빈으로
섞어 한 줄로 세운 뒤 전체를 비율대로 자른다. 전체 비율은 정확히 맞으면서 카테고리도 흩어진다.

**재현 가능한 무작위** — 파이썬 내장 `hash()` 는 실행마다 값이 달라지고(PYTHONHASHSEED),
`random.seed` 도 버전이 바뀌면 결과가 달라질 수 있다. `_common.stable_bucket()` 은
sha256 을 써서 어느 OS, 어느 실행에서도 같은 분할을 준다.

**하드 네거티브는 눈으로 확인한다** — 임계값을 잘못 잡으면 정답과 다를 게 없는 청크를
오답으로 학습시켜 모델을 오히려 망가뜨린다. 08 은 걸러낸 이유를 항목별로 세어 보여준다.
