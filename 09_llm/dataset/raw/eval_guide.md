# RAG 평가 가이드

## 검색 단계 평가

검색과 생성을 나눠서 평가해야 어디가 문제인지 알 수 있다.
검색 단계는 정답 청크를 알고 있어야 평가할 수 있으므로 골든셋이 먼저 필요하다.

Recall@k 는 정답이 상위 k 개 안에 있는지만 본다.
MRR 은 정답이 몇 번째에 있었는지까지 반영해서 순위 품질을 본다.
nDCG 는 정답이 여러 개일 때 순위별 가중치를 줘서 계산한다.

## 골든셋 만들기

질문과 정답 청크 id 를 짝지은 데이터가 골든셋이다.
FAQ 처럼 이미 질문과 답이 있는 자료가 있으면 그것부터 쓰는 것이 가장 빠르다.
문서 제목에서 질문을 만들어내는 방법은 규칙만으로 되지만 질문이 단조로워진다.
LLM 으로 질문을 생성하면 다양해지지만 사람이 검수해야 믿을 수 있다.

## 생성 단계 평가

근거 문서에 없는 내용을 지어냈는지, 질문에 실제로 답했는지를 본다.
정답 문자열과 비교하는 방식은 표현이 달라지면 점수가 떨어지므로 참고용으로만 쓴다.
평가셋은 데이터가 바뀔 때마다 갱신해야 하며 버전을 남겨야 비교가 가능하다.
